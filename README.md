## 📖 Project Overview

**NEURALVERSE** is not a conventional portfolio or static site. It is a **scroll-driven cinematic journey through an artificial intelligence system** — from boot sequence to neural core, from a touchable AI brain to a knowledge universe, from a demo AI assistant to a mission-control deck, ending in a poetic collapse into a single point of light.

**The core idea:** AI concepts — neural networks, brain regions, knowledge graphs, inference pipelines, future technology — are represented as **procedural 3D worlds** you move through, instead of paragraphs you read.

**Why it was created:** to demonstrate an AI/ML developer's range — *models plus meaning, pipelines plus presentation* — by rendering intelligence itself as an interactive WebGL experience, while keeping every word of content accessible even without a GPU.

**The experience:** a boot-style cinematic intro → a particle neural core that reacts to your mouse → five glowing brain regions you can hover and select → eleven knowledge nodes with travelling energy pulses → a staged assistant ritual → a cinematic project archive → stylized mission telemetry → a scroll-piloted flight through future tech → a 14-star skills constellation → about, contact terminal, and finale.

> **Honest scope:** the AI assistant runs on **curated local demo logic** (`demoAnswer`). No live model inference happens in the browser. An optional `VITE_AI_PROXY_URL` hook exists so a backend proxy can be wired later — it is not connected by default.

<details>
<summary><strong>What each layer does</strong></summary>

- **`App.tsx`** — owns intro state, locks scroll during boot, inits GSAP + Lenis, runs the global section-fade choreography, renders atmosphere, `NarrativeRail`, `Interstitial` tissue and all sections inside `ErrorBoundary`s.
- **`components/`** — reusable experience primitives. `SceneCanvas` is the most important: it only mounts a WebGL context when its section is near the viewport, keeping one scene on the GPU at a time.
- **`sections/`** — full narrative beats. Each owns layout, headings, 2D content and lazy 3D mounting (`React.lazy` + `Suspense` + `ErrorBoundary` + `WebGLFallback`).
- **`scenes/`** — pure R3F worlds. No routing, no data fetching — just geometry, shaders and pointer/scroll response.
- **`shaders/materials.ts`** — the visual DNA: one shared additive point-shader system plus hologram and energy-line materials and a canvas-generated glow sprite.
- **`data/`** — all content lives here, cleanly separated from rendering. `demoAnswer()` is the entire assistant "brain" — keyword-matched local responses.
- **`hooks/` + `utils/device.ts`** — capability sensing: device tier, touch, reduced-motion, WebGL, particle budgets and screen-reader announcements.
- **`lib/`** — animation infrastructure: GSAP registration and Lenis lifecycle.
- **`styles/globals.css`** — cinematic design system: film grain, tech grid, glassmorphism, holographic text, scanlines, custom cursor rules, focus rings and global reduced-motion kill-switches.

## ⚙️ Core Systems

- **Procedural particle generation** — clustered spheres (NeuralCore), ellipsoid cortex with fissure + sulci wobble (BrainScene), Fibonacci shell (UniverseScene), tunnel dust (FutureScene), disc + ambient dust (SkillsConstellation). All seeded with `Math.random()` at mount.
- **Custom GLSL materials** — `buildParticleMaterial()` composes per-particle `aScale` / `aColor` / `aPhase` attributes with `uTime` turbulence, twinkle and distance fade; hologram material adds fresnel + scanline + grid; energy-line material renders travelling pulses.
- **Particle link generation** — NeuralCore uses deterministic pseudo-neighbor strides (`+37`, `+91`, distance `< 3.4`, capped at ~14k floats) for **O(n)** web construction — no O(n²) neighbor search. Universe/Skills links are derived directly from data edges.
- **Energy / comet pulses** — NeuralCore lerps `budget.data` comets along random node pairs with arc lift; UniverseScene lerps 90 pulses along graph edges each frame.
- **Raycast interaction** — brain region cores and universe/skill nodes are real meshes with `onPointerOver/Out/Click` handlers; hover boosts brain particle brightness (recomputed only on selection change, never per frame) and cursor labels (`EXPLORE` / `OPEN` / `VIEW` / `ENTER`).
- **Camera movement** — pointer-lerped parallax + sinusoidal idle drift (NeuralCore, Brain, Universe, Skills); scroll-mapped dolly `z: 8 → -2` (FutureScene). All frozen under reduced-motion.
- **Scroll-driven animation** — Lenis smooth scroll + GSAP ScrollTrigger section crossfades (`opacity 0.55 → 1`, `scrub: 1`), per-section reveals, Finale collapse timeline, scroll-derived `progress` for the future tunnel.
- **Scene lazy loading** — every R3F scene is `React.lazy`-imported inside `Suspense` with a text fallback (`SYNTHESIZING CORTEX…`, `EXPANDING UNIVERSE…`, …).
- **Adaptive device tiers** — `getDeviceTier()` fuses `hardwareConcurrency`, `deviceMemory`, viewport width and touch coarse-pointer into `low | medium | high`; `particleBudget()` maps tiers to node counts, DPR ranges and bloom on/off.
- **WebGL detection** — `hasWebGL()` probes `webgl2` / `webgl` contexts; sections render `<WebGLFallback>` with full text content when unavailable.
- **Fallback rendering** — viewport-aware `STANDBY` placeholder when off-screen, `ErrorBoundary` (`VISUAL MODULE OFFLINE`) on crash, `noscript` block in `index.html`.
- **Cleanup / disposal** — RAF cancellation, resize/scroll/key listener removal, GSAP context revert + timeline kill, `destroyLenis()`, timer clearing in the assistant, R3F automatic geometry/material disposal.
- **Reduced-motion handling** — `prefersReducedMotion()` gates Lenis init, camera/particle motion, cursor, grain/holo animations (CSS), counters and sparklines; intro shortens from ~6.8s to ~1.2s with fewer particles.

## 🚀 Performance Engineering

No benchmark claims are made — only the strategies actually implemented:

- **Device-tier particle budgets** — NeuralCore `320 / 900 / 1800` nodes (+ `60 / 160 / 320` comets); Brain `700 / 1600 / 2600`; Future `900` dust; Skills `400` dust.
- **Adaptive DPR** — `particleBudget()` tiers map to DPR ranges; `SceneCanvas` renders at `dpr={[0.6, 1.5]}`.
- **Bloom control by device tier** — `bloom={tier !== 'low'}` on every scene; `EffectComposer multisampling={0}`, `antialias: false`.
- **Lazy-loaded scenes** — `React.lazy` + `Suspense` per 3D world so Three.js scene code splits out of the initial bundle (further split by `manualChunks`: `react` / `three` / `motion` in `vite.config.js`).
- **Viewport-aware canvases** — `useInViewport(ref, '700px')` ensures a WebGL context exists only near its section, keeping a single scene on the GPU at a time.
- **Error boundaries** — each section is wrapped so one failing visual never breaks the story.
- **WebGL capability detection** — no context is even attempted where WebGL is unavailable.
- **Reduced-motion handling** — skips Lenis, camera drift, comet/pulse loops and heavy CSS animation.
- **Capped rendering quality** — `stencil: false`, `powerPreference: 'high-performance'`, pixel-ratio clamp `Math.min(devicePixelRatio, 2)` in the particle shader.
- **Efficient link generation** — O(n) stride hashing instead of neighbor search; brain highlight recomputed on selection change, not per frame; throttled state updates (scroll, counters, sparklines).
- **Cleanup / disposal** — full teardown of loops, observers, timelines and smooth-scroll on unmount.

## ♿ Accessibility

- **Semantic HTML** — `header`, `main#main`, `section` with `aria-label`, `footer`, real `button`/`a`/`form`/`ol` elements throughout.
- **Keyboard / focus handling** — skip link (`Skip to content`), visible `:focus-visible` rings, tab-style region/project/skill selectors with `aria-selected`, toolbar roles, `Esc`/`Enter` to skip the intro.
- **ARIA** — `role="dialog"` + `aria-modal` (intro), `progressbar` (intro, processing), `img` + `aria-label` on every 3D canvas, `status` (fallbacks), `aria-live="polite"` announcer (`QUESTION RECEIVED… / RESPONSE READY…`) and response region.
- **Reduced-motion preference** — shortens intro, disables Lenis/cursor/camera/particle motion, stills grain/hologram animations, snaps counters to final values.
- **WebGL fallback** — every 3D panel degrades to a text fallback; all dossiers, skills, projects and contact links remain fully usable.
- **Interaction fallbacks** — touch devices get `TAP A REGION` guidance, larger targets and `touchMultiplier`; custom cursor only enables on `(pointer: fine)` without reduced-motion; `noscript` message preserves contact path.

## 📱 Responsiveness

| Context | Behavior (confirmed in source) |
|---------|-------------------------------|
| **Desktop** | Full experience: Bloom + Vignette, max particle budgets, mouse parallax, morphing HUD cursor, narrative rail (`xl` only) |
| **Mobile / touch** | Coarse-pointer + width heuristics drop to `low`/`medium` tiers; `touchMultiplier: 1.4`; tap guidance; responsive `sm:`/`lg:` grids; `min-h-[100svh]` hero; truncating contact rows |
| **Low-end devices** | Few cores / low memory / narrow screens → `low` tier: 320-node core, bloom off, smaller DPR, 40-particle intro |
| **Reduced-motion users** | No Lenis, no camera drift, static particles, instant counters, short intro, native `scrollIntoView` fallback |
| **No WebGL** | `WebGLFallback` panels replace every canvas; story, dossiers, projects, skills and contact remain intact |

## 💻 Installation

Prerequisites: **Node.js** (LTS recommended) and **npm**.

```bash
git clone https://github.com/hemanthhemanth1834-bit/neuralverse.git
cd neuralverse
npm install
npm run dev
```

| Command | What it does |
|---------|--------------|
| `npm install` | Installs dependencies from `package.json` |
| `npm run dev` | Starts Vite dev server, network-exposed (`vite --host`) |
| `npm run build` | Production build to `dist/` (chunk-split: `react` / `three` / `motion`) |
| `npm run preview` | Locally previews the production `dist/` build (`vite preview --host`) |
| `npm run start` | Alternate preview on `0.0.0.0:3000` (useful for container / Replit-style hosts) |

> `package.json` also sets `homepage` to the GitHub Pages URL and `vite.config.js` sets `base: '/neuralverse/'` so built assets resolve under that subpath.

## 🔐 Environment Variables

Defined in `.env.example` (copy to `.env` for local experiments; **never commit `.env`**):

| Variable | Required? | Purpose |
|----------|-----------|---------|
| `VITE_AI_PROXY_URL` | Optional | Backend proxy URL for future live assistant inference. Empty = local demo mode (current behavior). Read in `Assistant.tsx` but not yet used for fetching. |
| `VITE_SITE_URL` | Optional | Canonical site URL for metadata. Defaults to local dev URL in the example. |
| `VITE_DEMO_MODE` | Optional | `true` forces demo answers. Current assistant always answers locally regardless. |

```bash
cp .env.example .env   # Windows: copy .env.example .env
```

> ⚠️ **Security:** never put real API keys in `VITE_*` variables — they are bundled into client JavaScript and shipped to every browser. Live model calls must go through a backend proxy that keeps secrets server-side.

## 🌐 Deployment

**Primary target: GitHub Pages** (live at `https://hemanthhemanth1834-bit.github.io/neuralverse/`).

- `vite.config.js` → `base: '/neuralverse/'` keeps asset URLs correct under the project subpath.
- `package.json` → `homepage` matches the live URL; `index.html` canonical + OG URLs, `public/robots.txt` and `public/sitemap.xml` ship automatically from `public/`.
- Build output is static (`dist/`), so any static host works. Standard flow:

```bash
npm run build       # → dist/
# deploy dist/ to GitHub Pages (e.g. gh-pages branch / Pages action)
```

**Vercel compatibility note:** the app is a standard Vite SPA (`npm run build` → `dist/`), so it can deploy on Vercel with framework preset **Vite**. However, the committed `base: '/neuralverse/'` is GitHub-Pages-specific — for a Vercel root-domain deployment, change `base` to `'/'` (or remove it) before deploying, otherwise assets will 404.

## 🤝 Contributing

Simple, review-friendly workflow:

1. **Fork** the repository.
2. Create a branch: `git checkout -b feat/your-idea`.
3. Develop: `npm install` → `npm run dev`; keep changes scoped and accessible (keyboard + reduced-motion + fallback paths).
4. Test: `npm run build` and `npm run preview`; sanity-check desktop, mobile width, reduced-motion and WebGL-disabled states.
5. Commit with a clear message.
6. Open a **pull request** describing what changed, what you verified and any screenshots.

> Please never commit `.env` or secrets — only `.env.example`.

## 🧪 Code Quality / Engineering Notes

- **Modular architecture** — scenes, sections, components, data, hooks, lib, utils and styles each own one concern.
- **Component reuse** — `SceneCanvas`, `SectionHeading`, `MagneticButton`, `ErrorBoundary`, `WebGLFallback` shared across all chapters.
- **Separation of scenes / data / utilities** — content edits happen in `data/` without touching rendering; capability logic lives in `utils/device.ts`.
- **Device-aware rendering** — tier budgets, adaptive DPR and bloom gating flow from a single `useDevice()` hook.
- **Defensive WebGL handling** — detection → lazy mount → suspense → error boundary → text fallback at every 3D panel.
- **Animation lifecycle management** — GSAP contexts reverted, timelines killed, Lenis destroyed, observers/timers/RAF cleaned up, R3F disposal left to the reconciler.
